## 採用方式と残る作業

有料API・有料OCR・課金サービスは使用しません。許可された公式の構造化価格データが得られる場合を第一候補とします。現時点で使える公開価格APIは確認できていません。画像しかない場合、無料のTesseract等で候補を作ることは可能ですが、商品と価格の対応、税込・日替わり日付・会員条件の誤認があるためOCR結果を無審査で登録しません。

当面の代替は、利用許諾を確認できる情報源または店舗から直接提供された価格について、人が原本を照合して登録する方式です。店舗・野菜・税込価格・単位・開始終了日・確認日時・出典・条件・原文根拠を揃えます。店舗への問い合わせはまだ送信していません。

旧prices.jsonの3レコードは虚偽と断定したものではありません。原本照合前の状態はGitHubのコミット履歴（e348db6）に保存されています。その後公式画像で3件すべての一致を確認し、出典を公式ビューアに置換して確認根拠を追記。大根1/2カット1袋105.84円も確認し、計4件を登録しました。

## データと検証

`prices.json` の各価格は従来のフィールドに加え、`tax_included: true`、`verification_method: "manual_source_review"`、`evidence_text`（商品・価格・期間を確認した原文）、`conditions`（条件なしの場合も明示）が必要です。これらは人が原本を確認した記録であり、バリデータが内容の真偽を自動保証するものではありません。未来の販売開始日は保存可能ですが、販売開始前は画面に表示しません。異なる単位の最安は選びません。同じ単位でも産地・サイズ・会員条件等は出典で確認してください。

```sh
python -m unittest discover -s . -v
python collect_prices.py
python check_sources.py
```

`check_sources.py` はrobotsを先に確認し、店舗台帳で有効にした7店舗の公開HTMLを各1回だけ調査します。認証回避、リンク総当たり、画像複製は行いません。結果を `source_status.json` と Actions Summary に記録。掲載価格は生成しません。

Actionsは1ワークフローに統合。push/PRではテスト、月水金08:00 JSTと手動実行で検証・情報源診断・期限切れ削除を実行。公開リポジトリの標準Ubuntu runnerのみ使用し、外部有料サービスは呼びません。診断失敗と「価格なし」は区別します。データ更新と原本の価格確認日時は別です。

## ヤマキシの無料OCR候補収集

`collect_candidates.py` は公式川北店ページの「有効期限／川北店のチラシ」見出しにある食品チラシ2画像までを取得し、Tesseractの日本語OCRで野菜名の候補を抽出します。ActionsではUbuntu公式パッケージを使用し、有料APIや追加契約は使いません。月水金08時JSTの既存スケジュールと手動実行で処理します。

`review_candidates.json` は未確認の確認作業用ヒントです。価格・単位・商品別有効日は必ずnull。チラシ全体の日付を商品別販売日に流用しません。画像と全文OCRは一時ファイルだけに置き、リポジトリへ保存しません。画面は候補を価格として読まず、`collection_status.json` の読取状況だけを表示します。実画像では数字や日替わり列の誤読があり、完全自動の価格掲載には未到達です。

アクセスはHTTPS・同一ホスト（公式robotsのwww転送1件のみ明示許可）、robots確認、回数・容量・時間制限、1秒以上の間隔付き。401/403/429/5xx・robots拒否・通信障害・別ホストへの転送は停止し、再試行しません。robots未設置は再利用許諾ではなく、利用条件やサイトからの停止要請があれば収集を停止する必要があります。取得失敗時は前回候補と成功日時を保持し、失敗状況を別記録します。画像構造やURL命名が変われば追随せず要確認として停止します。

定期実行のGITHUB_TOKENによるコミットではPagesの再ビルドが起動しないため、画面の台帳・価格・OCR状況は公開リポジトリのrawデータを直接参照します。取得できない場合は同梱データへフォールバックし、有効期間の判定は継続します。GitHub側のキャッシュによる反映の遅延はあり得ます。未確認OCR候補ファイルは画面から取得しません。
